# Самостійна робота №15

**Тема:** Делегати й лямбда-вирази: власні утиліти для колекцій.

## 1. Чому делегати корисні для створення таких утиліт?

Делегати дозволяють передавати методи як параметри. Завдяки цьому можна створювати універсальні методи, які працюють з різними типами даних та умовами.

Func використовується для перетворення елементів, Predicate для перевірки умов, а Action для виконання дій.

Це дозволяє повторно використовувати один метод для різних колекцій, не створюючи окрему реалізацію для кожної задачі.

## 2. Як лямбда-вирази спрощують виклик цих методів?

Лямбда-вирази дозволяють коротко записувати логіку, яку потрібно передати методу.

Наприклад:

CollectionUtils.Filter(numbers, n => n % 2 == 0);

У цьому випадку лямбда-вираз перевіряє, чи є число парним. Не потрібно створювати окремий метод для такої простої умови.

Це робить код коротшим, зрозумілішим та зручнішим для повторного використання.

## 3. Порівняння власних методів з LINQ

| Власний метод | Аналог | Призначення |
|---|---|---|
| Map | Select | Перетворення елементів |
| MaxBy | MaxBy | Пошук максимального елемента за ключем |
| Filter | Where | Фільтрація елементів |
| ForEach | List.ForEach | Виконання дії для елементів |

LINQ має готові методи для роботи з колекціями. Власні методи дозволяють краще зрозуміти принцип роботи делегатів та лямбда-виразів.

Map і Filter у моїй реалізації одразу створюють нові списки, тоді як Select і Where використовують відкладене виконання.

Роботу методів перевірено на трьох різних колекціях: числах, рядках та товарах. У результаті я закріпив знання про делегати, лямбда-вирази та узагальнені методи.
