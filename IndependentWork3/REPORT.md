## Аналіз інкапсуляції в open-source проєкті

**Виконав:** Солонець Артем, ІПЗ-3/2  
**Обраний проєкт:** dotnet/runtime  
**GitHub:** https://github.com/dotnet/runtime

Для аналізу обрано класи `SerialPort` та `WinHttpHandler`. Обидва класи є частиною реального коду .NET і містять приватний стан, публічні властивості та перевірки вхідних значень.

## 1. Клас SerialPort

**Файл:**  
https://github.com/dotnet/runtime/blob/ad029a35a82f87a2b5ef4472abf9e5cefcae9f11/src/libraries/System.IO.Ports/src/System/IO/Ports/SerialPort.cs

`SerialPort` інкапсулює параметри послідовного порту. Значення зберігаються у приватних полях, наприклад `_baudRate`, `_dataBits`, `_portName`, `_readTimeout`. Зовнішній код не змінює ці поля напряму, а працює через властивості.

Невеликий фрагмент, що показує приватний стан:

```csharp
private int _baudRate = DefaultBaudRate;
private string _portName = DefaultPortName;
```

Властивість `BaudRate` повертає значення приватного поля, а в `set` перевіряє коректність нового значення. Якщо швидкість менша або дорівнює нулю, створюється `ArgumentOutOfRangeException`.

Фрагмент перевірки:

```csharp
if (value <= 0)
    throw new ArgumentOutOfRangeException(nameof(BaudRate), ...);
```

Це хороший приклад інкапсуляції: клас сам контролює допустимий стан і не дозволяє записати некоректне значення.

Також у класі є властивості лише для читання, наприклад `BytesToRead` та `BytesToWrite`. Вони надають інформацію про поточний стан, але не дозволяють користувачу напряму його змінювати.

## 2. Клас WinHttpHandler

**Файл:**  
https://github.com/dotnet/runtime/blob/ad029a35a82f87a2b5ef4472abf9e5cefcae9f11/src/libraries/System.Net.Http.WinHttpHandler/src/System/Net/Http/WinHttpHandler.cs

`WinHttpHandler` керує параметрами HTTP-з'єднання. Велика кількість налаштувань зберігається у приватних полях: `_automaticRedirection`, `_maxAutomaticRedirections`, `_cookieUsePolicy`, `_maxConnectionsPerServer` та інших.

Приклад приватного стану:

```csharp
private bool _automaticRedirection;
private int _maxAutomaticRedirections;
```

Для зміни стану використовуються публічні властивості. Властивість `MaxAutomaticRedirections` перевіряє, що значення більше нуля. Якщо перевірка не проходить, генерується `ArgumentOutOfRangeException`.

Фрагмент перевірки:

```csharp
if (value <= 0)
    throw new ArgumentOutOfRangeException(nameof(value), value, ...);
```

Властивість `CookieUsePolicy` також перевіряє, чи належить передане значення до допустимого набору. Крім перевірки значень, сетери викликають внутрішню перевірку стану об'єкта перед зміною налаштувань. Таким чином зовнішній код не може довільно змінити внутрішній стан у неправильний момент.

## 3. Порівняння підходів

В обох класах поля приховані за модифікатором `private`, а доступ до них організований через властивості. Це дозволяє додавати перевірки без зміни зовнішнього інтерфейсу класу.

У `SerialPort` валідація пов'язана переважно з фізичними параметрами порту. У `WinHttpHandler` перевіряються мережеві налаштування та допустимість зміни стану об'єкта.

Автоматичні властивості тут використовуються не всюди, оскільки для багатьох параметрів потрібна додаткова логіка у `get` або `set`. Саме тому приватне поле плюс ручна властивість є доречним рішенням.

Індексатори або перевантажені оператори в проаналізованих фрагментах не є основним механізмом роботи цих класів.

## 4. Висновок

На прикладі реального коду .NET видно, що інкапсуляція потрібна не лише для приховування полів. Вона дозволяє класу контролювати власний стан, перевіряти вхідні дані та не допускати некоректних значень. Валідація у властивостях робить помилки помітними одразу під час спроби встановити неправильне значення. На мою думку, такий підхід робить код надійнішим і спрощує його подальше використання.
