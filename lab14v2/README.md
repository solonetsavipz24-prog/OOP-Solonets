# Лабораторна робота №8

## Тема
Делегати й лямбда-вирази у практиці колекцій: `CollectionHelper<T>`.

## Варіант 2
Реалізовано метод `Map`:

```csharp
public static IEnumerable<TResult> Map<TResult>(IEnumerable<T> collection, Func<T, TResult> mapper)
```

Метод перетворює кожен елемент колекції типу `T` на елемент типу `TResult` за допомогою делегата `Func<T, TResult>`.

Ключова логіка реалізована власним кодом через `foreach` і `yield return`, без використання готового LINQ-оператора `Select` як рішення.

## Демонстрація
У `Main` метод `Map` продемонстровано для трьох різних типів колекцій:

- `List<int>` → `IEnumerable<string>`;
- `List<Product>` → `IEnumerable<decimal>`;
- `List<string>` → `IEnumerable<int>`.

У всіх викликах поведінка передається через лямбда-вирази.

## Контрольні запитання

### 1. Що таке делегат і для чого він використовується?
Делегат — це тип, який зберігає посилання на метод із певною сигнатурою. Він використовується для передавання поведінки як параметра.

### 2. У чому полягає різниця між `Func` та `Action`?
`Func` повертає значення, а `Action` виконує дію і нічого не повертає (`void`).

### 3. Як лямбда-вирази спрощують роботу з делегатами?
Лямбда-вирази дозволяють коротко описувати потрібну функцію прямо в місці передавання делегата без створення окремого методу.

### 4. Які переваги дають узагальнені методи при роботі з колекціями?
Вони дозволяють використовувати один і той самий код для різних типів даних, зберігаючи перевірку типів під час компіляції.

## Висновок
У роботі реалізовано узагальнений клас `CollectionHelper<T>` з методом `Map`, використано `Func<T, TResult>` і лямбда-вирази та продемонстровано роботу методу на колекціях різних типів.
