# Самостійна робота №14
## Тема: Вивчення Dictionary<TKey, TValue> та HashSet<T> у бібліотеках .NET

### 1. Аналіз використання колекцій у відкритих проєктах

Для аналізу було обрано відкритий проєкт .NET Runtime від Microsoft.

**Приклад 1. Dictionary<TKey, TValue>**

У файлі System.Linq/ToCollection.cs реалізовано метод ToDictionary. Він перетворює послідовність елементів на словник, використовуючи вибраний ключ для кожного елемента.

Така колекція використовується тому, що дозволяє швидко знаходити значення за ключем. Звичайний список для цього менш зручний, оскільки потребує послідовного перегляду елементів.

Середня складність додавання та пошуку за ключем становить O(1), а побудова словника з усієї колекції має середню складність O(n).

Особливістю реалізації є підтримка власного IEqualityComparer<TKey>. Це дозволяє змінювати правила порівняння ключів. Також ключі повинні бути унікальними.

**Приклад 2. HashSet<T>**

У файлі System.Linq/ToCollection.cs є метод ToHashSet. Він створює множину з переданої послідовності.

HashSet використовується для зберігання тільки унікальних елементів. Повторне додавання однакового елемента не створює дубліката. Це зручно для видалення повторів і перевірки наявності значень.

Середня складність додавання та пошуку елемента становить O(1). Для створення множини з усієї послідовності потрібно в середньому O(n).

Метод підтримує власний IEqualityComparer<T>, що дозволяє налаштувати правила визначення однакових елементів.

### 2. Висновки про вибір колекцій

Dictionary краще використовувати тоді, коли необхідно зберігати дані у вигляді пар ключ-значення та швидко знаходити інформацію за ключем. Наприклад, це може бути кеш файлів, користувачів або товарів.

HashSet оптимально підходить для зберігання унікальних значень, видалення дублікатів та виконання операцій над множинами. Він підтримує об'єднання, перетин і різницю множин.

Основні підводні камені: словник не допускає однакових ключів, а HashSet не зберігає повтори. Також важливо правильно обирати порівняння об'єктів. Якщо змінити поля об'єкта, які впливають на його хеш-код, після додавання до HashSet, пошук може працювати некоректно. Для рядків регістр символів враховується стандартним порівнянням, якщо не вказати власний comparer.

### 3. Порівняльна таблиця

| Операція | List | Dictionary | HashSet |
|---|---|---|---|
| Додавання | O(1) аморт. | O(1) середнє | O(1) середнє |
| Пошук за значенням | O(n) | O(n) | O(1) середнє |
| Пошук за ключем | N/A | O(1) середнє | N/A |
| Видалення | O(n) | O(1) середнє | O(1) середнє |
| Перевірка наявності | O(n) | O(1) середнє | O(1) середнє |

Для хеш-колекцій складність O(1) є середньою. У випадку великої кількості колізій вона може погіршуватися до O(n). У List додавання в кінець має амортизовану складність O(1), а вставка в середину потребує O(n).

### 4. Практична реалізація

У програмі було розроблено три класи.

FileMetadataCache використовує Dictionary для зберігання метаданих файлів. Реалізовано додавання, отримання, видалення та перевірку наявності файлу.

TagManager використовує Dictionary та HashSet для зберігання тегів статей. Реалізовано додавання, видалення, отримання унікальних тегів, пошук спільних тегів та різниці множин за допомогою UnionWith, IntersectWith та ExceptWith.

SearchIndex створює простий пошуковий індекс. Кожному слову відповідає множина ідентифікаторів документів. Реалізовано пошук за одним словом та за кількома словами одночасно.

Під час виконання програми перевіряється робота всіх трьох класів та виводяться результати в консоль.

### 5. Загальний висновок

Під час виконання роботи було досліджено можливості Dictionary<TKey, TValue> та HashSet<T> у .NET. Було розглянуто приклади їх використання у вихідному коді .NET Runtime та створено власний застосунок.

Я з'ясував, що Dictionary зручний для швидкого доступу до інформації за ключем, а HashSet допомагає працювати з унікальними значеннями та множинами. Обидві колекції корисні для створення кешів, пошукових систем та інших прикладних програм.
