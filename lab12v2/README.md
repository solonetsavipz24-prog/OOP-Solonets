## Структура

### `IEntity`
Базовий інтерфейс для сутностей. Містить властивість:

```csharp
int Id { get; set; }
```

### `IRepository<T>`
Узагальнений інтерфейс з обмеженням:

```csharp
where T : IEntity
```

Містить CRUD-методи:
- `GetById(int id)`
- `GetAll()`
- `Add(T item)`
- `Update(T item)`
- `Delete(int id)`

### `InMemoryRepository<T>`
Реалізація `IRepository<T>`, що зберігає дані у `List<T>`. Для неіснуючих елементів `GetById`, `Update` та `Delete` викидають `KeyNotFoundException`.

### `User`
Клас сутності варіанту 2. Реалізує `IEntity` та містить `Id`, `Username`, `Email`, `IsActive`.

## Контрольні запитання

### 1. Яка роль `where`-обмежень у Generics?
`where` задає вимоги до типу-параметра. Наприклад, `where T : IEntity` гарантує, що тип `T` реалізує `IEntity`, тому репозиторій може безпечно звертатися до властивості `Id`.

### 2. Навіщо потрібен шаблон `IRepository`?
`IRepository` відокремлює логіку роботи з даними від іншої логіки програми. Це спрощує заміну способу зберігання даних, повторне використання коду та тестування.

### 3. Чому юніт-тести важливі для узагальнених компонентів?
Generics можуть використовуватися з різними типами, тому тести допомагають перевірити, що основні операції працюють стабільно та передбачувано.

### 4. Які проблеми вирішують Generics порівняно з `object`?
Generics забезпечують перевірку типів на етапі компіляції, зменшують кількість приведень типів і ризик помилок, а також дають змогу створювати універсальний код без втрати типобезпеки.
